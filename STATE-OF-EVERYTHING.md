# 2. Where the website lives

    Duaa's laptop  ─┐
                    ├─→  GitHub  ─→  (you click Deploy)  ─→  takwafoods.com
    Your laptop    ─┘

**Three separate places, and only the last one is public.**

| Stage | What it is | Who can change it |
|---|---|---|
| A laptop | A full copy of the site, running at `localhost:8099` | Whoever is sitting at it |
| GitHub | `Takwa-Website/Takwa-website`, public | You and Duaa |
| The live site | cPanel, `/home/takwafood/public_html` | **You only** |

**Pressing Publish does not publish.** It sends work to GitHub. The live site
changes only when you click *Update from Remote* then *Deploy HEAD Commit* in
cPanel. That is the whole safety design.

# 11. If something breaks

| Symptom | Where to look |
|---|---|
| Live site wrong | A deploy question. cPanel → Git Version Control |
| Localhost wrong | An editing question. Restart the tools |
| She cannot publish | She should read the message — it says whether her work is safe. It always is |
| Tools will not open | Run the stop script, then the launcher again |
| Forgotten tools password | Delete `.takwa-tools-auth.json` in the website folder |
| Forgotten `/admin/` password | Delete `takwa-admin-config.php` in `/home/takwafood/` |
| Everything is wrong | Restore `01-site-and-scripts-COMPLETE.tar.gz` from the backup drive |

**The applications on the server are never affected by any of this.** They live
outside the web root and no deploy touches them.
